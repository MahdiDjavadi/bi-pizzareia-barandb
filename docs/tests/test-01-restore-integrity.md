# تست 01: بازیابی و صحت‌سنجی یکپارچگی داده‌ها
**فاز / مرحله:** P2 / S0-S1

## هدف
بازیابی بکآپ به عنوان یک دیتابیس جدید از یک سیستم عملیاتی، تایید صحت بازیابی ساختار دیتابیس، محافظت از منبع در برابر هرگونه تغییر.

## کاری که انجام شد
دیتابیس در یک پایگاه داده جدید بازیابی شد، با اجرای `DBCC CHECKDB` از نظر یکپارچگی بررسی شد و در نهایت در حالت فقط‌خواندنی (`READ_ONLY`) قرار گرفت.

اسکریپت: `sql/discovery/t01_restore_integrity.sql`

## نتیجه
| مورد | مقدار |
|---|---|
| Database name | BaranDb |
| Backup size | 272 MB حدود |
| Backup format (DatabaseVersion) | 957 (SQL Server 2022) |
| Database creation date | 2024-10-15 |
| Backup taken | 2025-12-22 18:07 |
| Restored on | SQL Server 2025 |
| Compatibility level | 160 (حفظ شد) |
| Collation | Persian_100_CI_AS (حفظ شد) |
| DBCC CHECKDB | بدون خطا |
| State | READ_ONLY |

## نکته مهم
اجرای دستور `CHECKDB` سلامت دیتابیس بازیابی شده را تایید کرد اما درباره داده های جدول ها، یکتایی کلیدها و orphanها چیزی مشخص نیست. نام کسب و کار، آدرس فایل ها و Hash فایل بکآپ به جهت حفظ محرمانگی نمایش داده نمی شوند.

## تفسیر
- محتمل: تاریخ ساخت دیتابیس (2024-10-15) زمان نصب یا مهاجرت این سیستم است، نه شروع کسب‌وکار.
- تاریخ بکآپ (2025-12-22) فقط زمان گرفتن نسخه است، نه تاریخ as-of کسب‌وکار. تاریخ as-of را از داده در T04 تعیین می‌کنیم.

## تصمیم
- D-001: سطح سازگاری و کالیشن دیتابیس منبع بدون تغییر باقی بمانند؛ کالیشن مناسب برای محیط‌های استیج و انبارداده در مراحل بعدی انتخاب شود.
- D-002: دیتابیس منبع در حالت فقط‌خواندنی نگهداری شود.
