# تست 01: بازیابی و صحت‌سنجی یکپارچگی داده‌ها
**فاز / مرحله:** P2 / S0-S1

## هدف
بازیابی بکآپ به عنوان یک دیتابیس جدید از یک سیستم عملیاتی، تایید صحت بازیابی ساختار دیتابیس، جلوگیری از هر گونه تغییرات.

## کاری که انجام شد
دیتابیس در یک پایگاه داده جدید بازیابی شد، با اجرای `DBCC CHECKDB` از نظر یکپارچگی بررسی شد و در نهایت در حالت فقط‌خواندنی (`READ_ONLY`) قرار گرفت.

اسکریپت: `sql/discovery/t01_restore_integrity.sql`

## نتیجه
| مورد | مقدار |
|---|---|
| Database name | BaranDb |
| Backup size | 272 MB حدود |
| Backup format (DatabaseVersion) | 957 (SQL Server 2022) |
| Database creation date | 2024-10-15 |
| Backup taken | 2025-12-22 18:07 |
| Restored on | SQL Server 2025 |
| Compatibility level | 160 (حفظ می شود) |
| Collation | Persian_100_CI_AS (حفظ می شود) |
| DBCC CHECKDB | بدون خطا |
| State | READ_ONLY |

## نکته مهم
اجرای دستور `CHECKDB` سلامت دیتابیس بازیابی شده را تایید کرد اما درباره داده های جدول ها، یکتایی کلیدها و orohanها چیزی مشخص نیست. نام کسب و کار، آدرس فایل ها و Hash فایل بکآپ به جهت حفظ محرمانگی نمایش داده نمی شوند.

## تفسیر
- تاییدشده: فایل بکآپ قابل بازیابی و ساختار دیتابیس قابل قبول است.
- برداشت شده: تاریخ بکآپ فقط کران پایین سیستم است نه شروع کسب و کار. یادداشت میکنیم تا با تحلیل بخش تاریخ در تست 4 بیشتر بررسی کنیم.


## تصمیم
- D-001: سطح سازگاری و کالیشن دیتابیس منبع بدون تغییر باقی بمانند؛ کالیشن مناسب برای محیط‌های استیج و انبارداده در مراحل بعدی انتخاب شود.
- D-002: دیتابیس منبع در حالت فقط‌خواندنی نگهداری شود.
